## 3. 语料完整性核查（澄清一次虚警）

检查过程中曾发现 `Get-FileHash(ziwei_corpus.json)` = `96dad292…`，与归档/7.3 报告记录的
`b1b8f90a…` 不一致。深挖结论：**非数据问题，为行尾符口径差**：

- pipeline 以 `write_text(encoding="utf-8")` 输出 **LF** 文本，其 sha 口径 =
  sha256(规范 LF 文本) = `b1b8f90a…`；
- 本机工作区检出的磁盘文件为 **CRLF**（3282 对，来自全局 `core.autocrlf`），原始字节
  sha = `96dad292…`；
- 以 LF 规范重建 pipeline 输出并与磁盘文件按文本比较：**逐字符一致**，节点/关系/引用
  计数 63/37/10 一致。

**建议（可选）**：在 `.gitattributes` 为 `knowledge/**/*.json`（或至少 `ziwei_corpus.json`）
固定 `text eol=lf`，消除"原始字节 hash ≠ 记录 hash"的口径歧义（项目已在 7.1.4A+
对 `context/*.md` 做过同类治理）。
