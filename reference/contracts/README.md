# Contracts Directory

> **Normative**: This directory contains **Architecture Contracts**
> for the open-metaphysics Reference Runtime.
> See: `docs/specification/RUNTIME_CONTRACT.md`

---

## Purpose

Architecture Contracts are the **canonical output specification**
of the Reference Runtime. They define the exact JSON structure and
content that every formal implementation (Rust, Go, Python, WASM)
must produce.

A Contract is **not** test data. A Contract is **not** a demo.
A Contract is a **binding specification**.

---

## Auto-Generation Rule (MANDATORY)

**All Contracts in this directory MUST be auto-generated by running
the Reference Runtime.**

### Prohibited Actions

- **MUST NOT** hand-write Contract JSON files.
- **MUST NOT** manually edit Contract files after generation.
- **MUST NOT** cherry-pick, add, or remove fields by hand.
- **MUST NOT** modify golden examples in Contract files.
- **MUST NOT** change `contract_version` without regenerating.

### Allowed Actions

- **MAY** regenerate a Contract by running the export function.
- **MAY** add a new Contract for a new layer (with a new export
  function).
- **MAY** delete a deprecated Contract (only after the deprecation
  grace period - see `CONTRACT_VERSIONING.md` Section 8).

---

## How to Regenerate

All five contracts are regenerated from the Reference Runtime:

```bash
python - <<'PY'
from reference.engine import export_rule_contract, CONTRACT_PATH as RULE
from reference.pattern_matcher import export_pattern_contract, CONTRACT_PATH as PATTERN
from reference.evidence_builder import export_evidence_contract, CONTRACT_PATH as EVIDENCE
from reference.knowledge_query import export_knowledge_contract, KNOWLEDGE_CONTRACT_PATH as KNOWLEDGE
from reference.consensus_builder import export_consensus_contract, CONSENSUS_CONTRACT_PATH as CONSENSUS

export_rule_contract(output_path=RULE)
export_pattern_contract(output_path=PATTERN)
export_evidence_contract(output_path=EVIDENCE)
export_knowledge_contract(output_path=KNOWLEDGE)
export_consensus_contract(output_path=CONSENSUS)
PY
```

### Verification

```bash
python -m pytest tests/test_reference_rules.py::TestRuleContract -v
python -m pytest tests/test_reference_patterns.py::TestPatternContract -v
python -m pytest tests/test_reference_evidence.py::TestContract -v
python -m pytest tests/test_reference_knowledge.py::TestContract -v
python -m pytest tests/test_reference_consensus.py -k contract -v
```

Every diff test asserts the committed contract matches the runtime
export, and the determinism test asserts two exports are identical.

## Contract File Format

All Contracts **MUST** follow this format:

```
Encoding:       UTF-8 (no BOM)
Line endings:   LF only (canonical; ACP-REF-002, 2026-10-24)
Key order:      sorted (sort_keys=True)
Indentation:    2 spaces
Ensure ASCII:   False (Chinese characters as literals)
Trailing newline: Yes
```

### Required Top-Level Fields

```json
{
  "contract_name": "<layer_name>",
  "contract_version": "<semver>",
  "description": "<human-readable description>",
  "generated_by": "<fully.qualified.function>",
  "models": { ... },
  "golden_examples": [ ... ]
}
```

See `docs/specification/RUNTIME_CONTRACT.md` Section 9 for the
complete format specification.

## CI Enforcement

The CI Merge Gate verifies that:

1. The committed Contract file matches what the Reference Runtime
   would generate right now (Contract Diff).
2. If they differ, the merge is **BLOCKED**.
3. The only way to update a Contract is to regenerate it from the
   Reference Runtime.

See `docs/specification/RUNTIME_CONTRACT.md` Section 5.3 for
Contract Diff details.
