## 1. 裁定依据（Phase 6.7.1.5）

- sxtwl 是 `compute()` 路径内唯一外部历法依赖, 农历输出直接进入命宫/
  五行局/定局计算 —— 版本变动可能静默改变排盘结果。
- 原范围声明 `sxtwl>=1.6` 已跨大版本解析（环境实测安装 **2.0.7**）。
- 精确 pin + 历法向量回归 = 唯一可审计的确定性保障; 未来升级须 ACP +
  向量迁移 + 全量回归。

## 2. 变更前后对比

| 项 | Before | After |
|----|--------|-------|
| pyproject.toml | `"sxtwl>=1.6"` | `"sxtwl==2.0.7"` |
| 环境实测 | sxtwl 2.0.7 | 2.0.7（一致） |
| 行为 | 无变化 | 无变化（pin 不改运行时行为） |

## 3. 验证方法

- 3 例历法数值测试（`test_lunar_conversion_2024_05_01` / `_2024_02_10` /
  `_leap_month_2023`）—— 已锁定 2.0.7 输出。
- replay 测试 + Phase 6.7.2 历法向量（ZV-lun-001~003）纳入机器回归。
- 全仓库 578/578; ruff 通过。

## 4. 向量迁移影响声明

- pin 无行为变化, 无向量迁移。
- 历法数值向量以 2.0.7 输出为基准生成; 任何升级须 ACP + 向量迁移。
